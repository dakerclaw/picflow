# PicFlow - 图片分享网站

一个可以自己部署的图片分享网站：瀑布流浏览、多图上传、标签与作者筛选、点赞、单张照片分享，可选「整站访问密码」。

前端 React 18 + Vite + Tailwind CSS，后端 Node.js + Express，数据用 SQLite（sql.js，纯 JS 免编译），支持 Docker 与 Linux 裸机两种部署。

## ✨ 功能介绍

| 功能 | 说明 |
|------|------|
| **瀑布流布局** | 响应式自适应 1~6 列，随窗口宽度动态调整 |
| **缩略图加速** | 列表用缩略图（约 50KB）、点开才是原图，首屏流量降一个数量级；图片长缓存，复访不再重复下载 |
| **接口优先** | 列表图片限量并发下载，始终给登录/点赞/后台等接口留出连接，弱网下点哪都是秒开 |
| **图片预览** | 全屏灯箱，**滚动鼠标滚轮**连续上下切换图片 |
| **多图上传** | 拖拽或点击选择，支持 JPG/PNG/GIF/WebP/BMP/AVIF，单张最大 50MB |
| **账号系统** | 注册/登录，JWT 认证，个人主页管理 |
| **点赞收藏** | 一键点赞，实时计数 |
| **图片下载** | 卡片和预览页均可直接下载 |
| **图片分享** | 一键复制链接，支持微博/Twitter 分享 |
| **搜索过滤** | 按名称、标签、作者实时搜索 |
| **标签 / 作者筛选** | 顶部按钮列出全站标签与作者，点选即筛选（服务端分页） |
| **全局访问密码** | 开启后整站加密，输入密码才能浏览，支持后台随时开关/改密 |
| **响应式设计** | 桌面端/平板/手机全适配 |

## 📁 项目结构

```
picflow/
├── src/
│   ├── index.js              # Express 入口（API + 静态文件服务 + 访问密码闸门）
│   ├── config.js             # 路径与运行时配置
│   ├── database.js           # SQLite（sql.js）封装
│   ├── thumbnails.js         # 缩略图生成（sharp 可选，缺了就自动退回原图）
│   ├── image-gate.js         # 列表图片限流，给接口请求留出连接
│   ├── middleware/
│   │   └── auth.js           # JWT 鉴权中间件
│   └── routes/
│       ├── auth.js           # 注册/登录/个人信息 API
│       ├── photos.js         # 图片上传/列表/点赞/删除 API
│       ├── settings.js       # 站点设置 API
│       ├── admin.js          # 管理员 API（用户管理、访问密码）
│       └── gate.js           # 全局访问密码（校验/开关/令牌）
├── dist/                      # 前端构建产物（已内置，无需自己构建）
│   ├── index.html
│   ├── share.html             # 单张照片的分享页
│   ├── gate.html / gate.css   # 未解锁时展示的密码页
│   └── assets/                # 前端 JS / CSS
├── uploads/                   # 图片文件存储目录（缩略图也在里面，文件名带 thumb_ 前缀）
├── data/                      # 数据库与密钥（Docker 部署时生成）
├── install.sh                 # 一键安装脚本（Linux 裸机）
├── deploy.sh                  # Linux 部署脚本
├── Dockerfile                 # Docker 镜像构建
├── docker-compose.yml         # Docker Compose 一键部署
├── .env.example               # 环境变量模板
└── package.json
```

图片在 `uploads/`，数据库在 `data/`（裸机安装时在项目根目录），这两处是你的全部数据，**备份和迁移只需要它们**。

## 🚀 安装

### 方式一：Docker（推荐）

需要先装好 Docker 与 Docker Compose：

```bash
git clone https://github.com/dakerclaw/picflow.git
cd picflow
docker compose up -d
```

然后浏览器打开 `http://服务器IP:3000`，第一个注册的账号自动成为管理员。

- 图片与数据库挂载在宿主机的 `./uploads`、`./data`，删除容器不影响数据
- 改端口编辑 `docker-compose.yml` 里的 `"3000:3000"`（冒号前是宿主机端口）
- 首次启动会自动生成一个随机 JWT 密钥保存到 `data/.jwt-secret`，不需要手动配置；**这个文件请和数据一起备份**

### 方式二：一键脚本（Linux 裸机）

需要 root 或 sudo，脚本会自动安装 Node.js 22、安装依赖、生成 `.env`，并让你选择用 PM2 / systemd / nohup / 前台方式启动：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/dakerclaw/picflow/main/install.sh)
```

默认安装到 `~/picflow`，也可以指定目录：`bash install.sh /你的/目录`。

已经克隆下来的话，直接执行：

```bash
git clone https://github.com/dakerclaw/picflow.git && cd picflow && bash install.sh
```

装完脚本会打印访问地址，默认 `http://服务器IP:3000`。

### 方式三：手动安装

需要 Node.js 18+（推荐 22）：

```bash
git clone https://github.com/dakerclaw/picflow.git
cd picflow
npm install --omit=dev
cp .env.example .env      # 端口、目录等都在这里；JWT_SECRET 可以留空，服务端会自己生成随机密钥
npm start                 # 按 .env 里的配置，默认 http://localhost:3000
```

> 没建 `.env` 时也能跑，端口是 3001。`.env` 只在启动时读一次，改完要重启进程。

## 🔄 更新

先把代码更新下来，再重建 / 重启。**图片和数据库在 `uploads/`、`data/`（裸机在项目根目录），更新不会丢数据。**

Docker 部署：

```bash
cd picflow
git pull
docker compose up -d --build
```

裸机部署（按当初的启动方式选一条）：

```bash
cd ~/picflow && git pull && npm install --omit=dev
pm2 restart picflow                     # PM2 启动的
sudo systemctl restart picflow          # systemd 启动的
```

> 跨大版本更新时，签发登录令牌与分享链接的密钥可能发生变化 —— 这时已登录的用户需要重新登录、之前发出去的分享链接需要重新分享；图片和数据库完全不受影响。

### 关于缩略图

列表页用的是一张最长边 720 像素的缩略图（原图约 2MB，缩略图约 50KB），点开看大图时才是原图。它由 `sharp` 生成，写在 `package.json` 的 **optionalDependencies** 里：装不上也不会让构建失败，服务端会自动退回「列表直接用原图」的老行为，功能不受影响，只是慢。

更新后如果列表的图片体积没有下降，按这两条查：

```bash
docker compose logs --tail=50 app | grep thumb      # 应看到「[thumb] sharp 已加载」
```

- 看到「未安装 sharp」：说明依赖没装上。在部署目录执行 `npm install sharp` 后重启即可；构建时拉不到 npm 源也会是这种情况。
- 缩略图是**首次访问时按需生成**的（一张约 0.1 秒），所以刚更新完第一次打开某一页会稍慢，之后就一直命中磁盘。已上传的老照片不需要任何迁移。

小内存机器上想彻底关掉它（省一点 CPU），在 `.env` 里加 `THUMBS_DISABLED=1` 重启即可。

### 关于「点哪个按钮都要等一会儿」

浏览器对同一个域名只开 **6 条并发连接**。列表页一次要下 20 张图，如果这 6 条全被图片占住，页面上的接口请求（登录、点赞、打开管理后台）就只能排队等着 —— 等待期间界面停在「加载中…」，看起来像是服务端慢，其实服务端处理这些请求通常只要几毫秒。

所以服务端会主动限流：**列表缩略图最多同时下载 4 张**，任何时候都留 2 条连接给接口；同时列表只加载进入视野的图片。点开大图、下载走的仍是原图，不受这个限制。

默认值 4 对绝大多数部署都合适。想改的话在 `.env` 里设置：

```bash
IMAGE_CONCURRENCY=4     # 列表缩略图的同时下载数；设 0 关闭限流（退回浏览器原生行为）
```

调低（例如 2）会让接口更稳但图片更慢；调高到 6 等于关闭。这个开关只影响列表图片的加载节奏，不影响图片数量、画质和任何功能。

## 🗑 卸载

Docker 部署：

```bash
cd picflow
docker compose down --rmi all --volumes
cd ..
rm -rf picflow
```

裸机部署（先停掉服务，再删目录）：

```bash
pm2 delete picflow && pm2 save          # PM2 启动的
# sudo systemctl stop picflow && sudo systemctl disable picflow \
#   && sudo rm /etc/systemd/system/picflow.service && sudo systemctl daemon-reload   # systemd 启动的

rm -rf ~/picflow
```

> `--volumes`（Docker）和 `rm -rf`（裸机）都会连同 `uploads/` 里的所有图片、`data/` 里的数据库和密钥一起删除，**不可恢复，请提前备份**。

## 🖥 使用指南

### 账号

- **注册**：右上角「注册」，第一个注册的账号自动成为管理员
- **登录 / 退出**：右上角「登录」；登录后点右上角头像进个人主页，在个人主页里可以退出登录

### 上传图片

1. 登录后点击右上角「上传」
2. 拖拽或点击选择图片（支持多选，单张最大 50MB）
3. **（可选）在「标签」输入框填写标签**，多个用逗号分隔（中英文逗号、分号、空格都行）；留空就不设标签
4. 点「上传」确认

支持 JPG / PNG / GIF / WebP / BMP / AVIF，**不支持 SVG**（SVG 能在浏览器里跑脚本，为安全起见不接受）。

服务端判定图片类型只读文件内容，不看文件名、也不看上传时声明的类型，所以：

- 把 `.html`、`.svg`、纯文本改名成 `.png` 再上传会被拒绝，并告诉你哪几个文件不合格（整批拒绝，不会一半成功一半失败）
- 真图片即使后缀写错（例如 PNG 存成 `.jpg`）也能正常上传，落盘时会按真实类型存成 `.png`

上传成功会提示「✓ 上传成功」并关闭弹窗（标签输入框同时清空，避免下一批被悄悄打上上一批的标签）；失败时弹窗**不会关闭**，已选文件和标签都保留，底部用红字给出服务端的真实原因，可以直接重试。

### 浏览与搜索

- 首页是响应式瀑布流，窗口越宽列数越多（1~6 列）
- 顶部搜索框按**名称 / 标签 / 作者**实时筛选
- 搜索框下方有「标签」「作者」两个按钮，点开即列出**全站所有标签 / 所有作者**（带图片数量），点选即筛选，再点一次取消；「清除筛选」一键回到全部
- 列表默认一次加载 **20 张**，底部「加载更多」追加下一页，全部加载完后按钮自动消失；新加载的一页作为一整块接在已有内容下方（向下生长，不会挤进右侧列）
- 列表里显示的是**缩略图**（最长边 720 像素，约 50KB），点开灯箱才是原图；图片带一年长缓存，同一个文件不会重复下载

### 预览图片

- 点击图片进入全屏灯箱，灯箱里会显示这张照片的标签
- **滚动鼠标滚轮**可以连续切换上一张 / 下一张
- 按 `ESC` 或点右上角 × 关闭

### 分享单张照片

- 打开照片 → 点灯箱里的「分享」→ 复制链接，或一键分享到微博 / Twitter（微信是复制链接后粘贴）
- 链接形如 `/share/<photoId>?t=<令牌>`，对方打开**只看得到这一张，不需要站点密码**
- 删除照片后该链接立即失效

### 直接打开某张照片

- 在站内用 `/?photo=<photoId>` 可以让应用启动后自动展开这张照片的灯箱，刷新后依然生效
- 若这张照片还没加载出来，应用会自动继续翻页把它找出来

### 开启全局访问密码

开启后整站加密：未通过验证的访客只能看到密码输入页，页面、图片、接口一律拒绝访问。

1. 用管理员账号登录（第一个注册的账号就是管理员）
2. 点顶部导航的「管理」进入后台
3. 切到「🔐 访问密码」页签
4. 打开开关、设置密码（可选填提示语、调整有效期），点「保存设置」，**立即生效**，无需重启服务

- 全新安装时**默认是关闭的**，整站公开，不做任何操作即可
- 关掉开关就恢复公开访问，密码会保留，重新打开不用再设一次
- 开启保护前必须先设置密码：若开关已打开但没有密码，前端会提示「请先设置访问密码」，服务端也会拒绝该请求，不会出现「显示已开启、实际仍可匿名访问」的假成功状态
- **反向代理环境**：站点前面挂了 nginx / Caddy 等反代时，需要在 `docker-compose.yml`（或 `.env`）里把 `TRUST_PROXY` 设为 `1`，否则所有访客会被当成同一个 IP，密码连续输错 10 次会把**全站**锁 10 分钟；反过来，如果容器端口能被公网直连，就保持关闭，否则别人伪造 `X-Forwarded-For` 就能无限次试密码
